# SSH connections

The **SSH** tile in the left rail opens the **SSH view** as a tab in the main area, next to your grids. It is a small SSH client built into the grid: it uses the built-in `ssh2` library (no `ssh` program is needed) and runs every session in the Pty Host, next to the local terminals.

- **SSH mode.** While the SSH view is in front, the left side panel shows the SSH sections instead of Projects, Files and Git: **Hosts**, **Keys**, **Known hosts** and **SFTP** (see below). The Projects, Files or Git tile, or a grid or file tab, brings the normal side panel back; the SSH tile folds and unfolds the side panel, and with the side panel folded the view shows the sections as a row at the top.
- **Hosts.** Search, **New host**, **New key** and **Bulk send** at the top, then a **Groups** row with **All** and one tile per group (click a group to show only its hosts; its menu has **Open as grid**; the row is hidden while no host has a group), and the hosts as tiles by group (label, user@host and a dot that shows whether a session to it is connected; hosts without a group come last under **No group**). Click a host to see and edit it in the details pane on the right; double-click or **Connect** opens it in the active grid, **Open in a new grid** in a new tab. Ctrl/Cmd+click selects several hosts and **Open as grid** opens them as one SSH-only grid; typing in the search keeps only the selected hosts that are still shown. Every group has its own **Open as grid** button. Local shells are opened from the **Add** menu and the terminal tabs.
- **Details pane.** It appears only while a host or key is chosen (or **New host** / **New key** is open); with nothing chosen the tiles use the whole width. The **X** in its corner, **Esc** with the focus in the pane or a second click on the shown tile closes it. With unsaved changes it asks first, also before showing another host or key, switching the section or closing the SSH tab; **Cancel** keeps the item and the edits. Going to a grid, a file or Settings (also through **Connect** or **Open as grid**) does not ask: the view stays open in the background with the pane and its draft, only typed passwords and passphrases are cleared.
- **Keys.** Key tiles (label, type, fingerprint); **New key** generates one or adds one from a file or pasted text, and a click on a tile opens the key in the details pane (label, public key, private key, certificate, passphrase, delete).
- **Private key.** In the key's details: **Show private key** shows the stored key text after a confirmation, with **Copy** and **Hide key** (a key with a passphrase is shown as stored, still encrypted; a copied key is cleared from the clipboard after a minute, or when the app quits before that, if it is still there; reloading the window does not stop the clearing); **Save private key to file...** writes it to a file you choose; **Replace private key** takes a pasted key (and its passphrase, if it has one), keeps the label and the hosts that use the key, and tells you whether the public key changed, in which case the new public key must be added to `authorized_keys` on the servers and a stored certificate (which belonged to the old key) is removed. A read-only vault cannot be changed.
- **Known hosts.** The trusted host keys (host, key type, fingerprint, date) with **Remove**; the same list as in **Settings > SSH**.
- **SSH cells in any grid.** The **Add** menu above the grid and a cell's menu list your hosts like profiles: pick one to add an SSH cell to the current grid. The grid dialog and presets can hold SSH cells too.
- **Saved hosts.** Save hosts with a label, address, port, user, group and tags; search them, fold groups, duplicate or delete them.
- **Key types.** Generate Ed25519, ECDSA (256, 384, 521) or RSA (3072, 4096, 2048) keys, or add one from a file (picker or drag and drop) or as pasted text: OpenSSH keys, PEM RSA and EC keys and PuTTY PPK v2 RSA keys. PuTTY PPK v3 keys must be saved as OpenSSH in PuTTYgen first. Copy the public key for `authorized_keys`; the private key leaves the vault only when you save it to a file or show it (see **Private key**). Certificates can be stored but are not used to sign in yet. ML-DSA and other post-quantum keys are not offered: there is no standard SSH signature for them and servers do not accept them.
- **Signing in.** Public key, saved password, password prompt and keyboard-interactive (one-time codes). A passphrase you type can be remembered until the app quits, so a grid of cells on one key asks once.
- **Host keys.** The first connection shows the server's fingerprint and asks whether to trust it; a changed key shows a red warning and connects only after you confirm the replacement. Trusted keys are listed in **Known hosts** of the SSH view and in **Settings > SSH**.
- **Startup command** per host: typed into the shell after login, line by line as if you typed it.
- **Bulk send.** One command for the checked SSH sessions of the current grid (SSH view button, palette, grid tab menu).
- **No session restore.** Sessions are not restored after a restart of the app; the cells show a **Connect** card, unless the host asks to reconnect (see below). A dropped connection is not reconnected by itself.

## Reconnecting

- **Reconnect when the app starts.** A checkbox in the host's details, off by default. When it is on, the SSH cells of that host connect by themselves after the app starts, each when its grid is shown (a grid in a tab you have not opened yet connects when you open it). A host that asks for a password, a key passphrase or an unknown host key still asks in the cell, as for a manual **Connect** (a cell that is not on screen also shows a toast). Reloading the window or a restart of the terminal process is not an app start: sessions that are still running are picked up as always, ended ones keep the **Connect** card or the reconnect bar.
- **Reconnect all SSH.** In the grid tab menu and the command palette (**SSH: reconnect all**), shown while the grid has SSH cells that are idle, ended or failed. It connects exactly those cells; connecting and connected ones are left alone.

## SFTP

The **SFTP** section of the SSH view is a file manager for a saved host: this computer on the left (the drives on Windows, the home folder on macOS), the server on the right and the transfer queue at the bottom. It logs in with the same keys, passwords, prompts and known hosts as an SSH cell. Open it from the SSH side panel, a host's menu, an SSH cell's menu or the command palette; **Change host** picks another saved host.

- **Transfers.** Drag files and folders between the panes, or use **Upload to the server** / **Download**. Folders transfer with everything in them; the queue shows progress, speed and errors and can cancel or retry an item. A name that already exists asks **Overwrite**, **Skip** or **Keep both** (optionally for the rest of the batch). A file is written under a temporary name and renamed into place only when it is complete.
- **Files and folders.** New folder, rename, delete on the server (after a count of what goes) and move to the trash on this computer.
- **Moving.** Drag entries onto a folder of the same pane, or use **Cut** and **Paste** (also **Paste here** on a folder). A folder is never moved into itself and never merged into another one. On the server a move is a rename; on this computer a move to another drive copies everything first and deletes the originals only when every copy is complete.
- **Permissions.** **Permissions...** on server entries shows the mode as an octal value and a grid (owner, group, others, plus setuid, setgid and sticky). **Apply to contents** sets one value for folders and another for files in the whole tree; links are skipped and never followed.
- **SFTP through sudo.** A host option, **Run SFTP through sudo**, starts the server's SFTP program through sudo, so the SFTP view sees and changes files as root (an optional **SFTP server command** replaces the usual `sudo -n` with the common sftp-server paths). The sudo password, when sudo needs one, is asked in the SFTP view and is never saved. A server without `lsetstat` cannot change permissions without following links: through sudo a recursive change is then refused, and a single change asks for a confirmation first.
- **Editing in tabs.** **Open** (or a double-click) opens a file in an editor tab next to your grids: text files up to 8 MB can be edited, images are previewed and binary or larger files offer a download. A save writes a temporary file next to the original and renames it into place, keeps the file's encoding, line endings and permissions, and is refused when the file changed on the server since it was read (with reload, diff and overwrite choices). Unsaved changes are kept as drafts, also across a restart. Tabs follow moves and renames done in the SFTP view; a tab whose file was moved or deleted elsewhere says so. Local files from the left pane open the same way (files inside a project open as project files).
- **Editor tabs of sudo hosts.** Editor tabs always read and save with the SSH user's own rights, also for a host with **Run SFTP through sudo**: they use a separate session without sudo. A file only root can read does not open in a tab, and a file in a folder the SSH user cannot write to cannot be saved there.
- **Connection.** The view holds one session at a time. A session disconnects 2 minutes after the SFTP view was closed and its queue is empty; a session that editor tabs with unsaved changes use stays connected (never a sudo session).

## Where secrets live

Hosts are stored in `state.json` without secrets. Keys and saved passwords are stored in `ssh/vault.json` in the app data folder, encrypted with Windows DPAPI or the macOS Keychain (`safeStorage`). When the system encryption is unavailable they are kept in memory only until the app quits and nothing secret is written. Trusted host keys are in `ssh/known_hosts.json`.

The app never reads `~/.ssh` by itself. On macOS the Keychain may ask again for access to "unimux Safe Storage" after an update.

The main process handles host keys, keys and passwords and passes secrets to the Pty Host in memory only.

The private key text reaches the app window only through **Show private key**, an explicit action you confirm first. It is returned as stored (a key with a passphrase stays encrypted; the passphrase is never used to decrypt it for display), lives only in that part of the key's details and is dropped on **Hide key**, when the details pane closes or goes to the background, on another key and after 2 minutes. It is never written to `state.json`, a log or a notification. **Replace private key** sends the pasted key to the main process, which checks it like an import and stores it like any other key (encrypted, or in memory only while the system encryption is unavailable); the form is cleared as soon as it is sent. A passphrase typed for the old key is never remembered for the new one.

## Not supported yet

Agent forwarding and ssh-agent/Pageant, jump hosts and proxies, port forwarding, mosh, per-host environment variables, importing `~/.ssh/config` or `known_hosts`.
