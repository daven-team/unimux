# unimux 1.1.4

A release about the AI team: workers that really start with their task, a coordinator that knows what happens, and a panel that shows a stuck team and fixes it in one click.

- **Workers start with their task again.** Recent Claude Code versions read every word after `--mcp-config` as one more config file, so a worker created by a coordinator took its own task for a file, stopped at once with "Invalid MCP configuration: MCP config file not found" and the task stayed queued. The task now goes first, before the options. A worker that starts again (after a failed start, by "Uruchom ponownie" or from the panel) gets its open tasks, and a worker that waits for another task (`after`) gets it only once that task is done.
- **The coordinator delegates by itself.** Settings > Agents has a new "Zespół AI: koordynator" group: "Sam, gdy się opłaca" (the default: a large task that splits into independent parts is given to a team the coordinator creates, small ones it does itself, and it always says what it delegated) or "Tylko na prośbę", plus the most agents at once (4 by default). The rules reach the agent through its system instructions at launch, so there is no need to write "use the unimux MCP" any more.
- **The coordinator knows what happens.** `wait_for` reports at once when a worker's CLI ended (with its exit code), when a worker never connected or waits for the user ("stalled"), and when its grid was closed; `list_agents` shows each agent's MCP connection and for how long it has been in its state. Waits last longer (up to 10 minutes for Claude Code, almost 3 for Codex), so a coordinator spends fewer turns waiting.
- **New tasks and messages reach a running worker.** A short notice ("new task ...: read_inbox") goes through the prompt queue when the worker sits at its prompt, for Claude Code and Codex.
- **Dead workers can be revived.** `update_agent` with `restart` starts an exited worker again with its tasks, and every answer says whether it restarted.
- **No more orphaned tasks.** Closing or archiving a grid cancels its open tasks ("agent closed") and tells the waiting coordinator; tasks left behind by older versions are cleaned up at start, so the AI team count in the title bar is right again. A queued task can be given to another agent.
- **The AI team panel shows a stuck team.** Tasks show how long they are in their state ("W kolejce od 4 min"); badges say "Agent nie wystartował", "Agent zakończył działanie (kod 1)" or "Czeka na Ciebie"; a banner at the top lists the stuck agents with "Uruchom ponownie z zadaniem" and "Pokaż agenta", and the Agents tab marks ended and never started agents.
- **Leaner tools.** The tool descriptions are shorter, workers see only the tools they use, a closed task in `wait_for` no longer returns at once in a loop, and every error tells the model what to do next.
- **Windows PowerShell by its full path.** Cells that use Windows PowerShell start it from its system folder.

Validated with the full test suite, the real Claude Code 2.1.318 and Codex 0.162.1 command lines and MCP waits (`scripts/verify-cli-contract.mjs`, `scripts/verify-mcp-cli.mjs`), and real-app checks of a coordinator creating workers in the background with PowerShell and cmd, a worker whose CLI fails, a worker that never connects, dependent tasks, closed grids and the panel (`verify-team-start`, `verify-mcp-team`, `verify-team-stuck`, `verify-team-panel`, `verify-mcp-app`).
