# unimux 0.9.8

- **SFTP.** The SFTP section of the SSH mode opens a file manager with your computer on the left and the server on the right, like Termius. Pick one of your saved hosts and it logs in the same way as an SSH cell (saved keys and passwords, the known hosts check, the password and host key questions shown in the view). Browse both sides with back, forward and up, drives on Windows, sorting and a filter; the server side also shows permissions and owner. Create folders, rename, delete (on the server always after a confirmation that names what goes, on your computer to the trash).
- **Transfers.** Drag files and folders between the two sides, or straight from the desktop or Explorer, or use Upload and Download. Folders go with everything inside. A panel at the bottom shows each transfer with progress and speed, and lets you cancel, retry and clear. If a file already exists you choose Replace, Skip or Keep both, also for all the rest at once. A file being transferred is written under a temporary name and gets its real name only when it is complete, so a cancelled or broken transfer never leaves half a file in place of the old one.
- **Open SFTP from where you are.** "Open SFTP" in a host's menu in the SSH view, "Open SFTP here" in the menu of a connected SSH cell (it opens the folder the cell's shell is in, when the shell reports it), and "SFTP: connect to host" in the command palette. unimux remembers the last folder on your computer and on each server.
- **Lighter with many agents.** The "working" dot and the loading spinners no longer animate continuously (they blink calmly once a second), which made the graphics card redraw the whole window up to 240 times a second: one working agent used about 44% of a CPU core and now about 2%; 20 busy terminals went from about 122% to about 30%. Terminals nobody is typing in collect their output a little longer before drawing it, while the one you type in still echoes at once.
- **Less memory.** Each terminal's background helper gets a small memory limit (about 4 MB less per terminal; the terminal process of a 20-cell grid went from about 325 MB to about 215 MB).
- **Terminal history length is a setting.** Settings > Terminal now chooses how many lines each terminal keeps: 1000, 2500, 5000, 10000 or 25000. The default is now 5000 (it was 10000), which saves about 80 MB with 20 busy terminals; pick 10000 or more to keep the old length. Shortening it drops the oldest lines of open terminals.

Validated with the full test suite on Windows and macOS, the no-console start check, the new perf check (no continuous animation while agents work, idle CPU under 1%), and real-app checks against a local SSH test server with SFTP (key and password login, the host key question, browsing, folders, rename, delete, uploads and downloads of files and folders, every conflict choice, cancel without leftovers, drops from the desktop, Open SFTP here) plus all earlier SSH, Git, layout, worktree safety and close confirmation checks.
