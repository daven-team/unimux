# unimux Tauri migration: work packages (all at once)

See ARCHITECTURE.md for the design and INVENTORY.md for the 1.1.4 behaviour every package must keep. Effort is in agent-days (one agent, one working day). Packages are sized 1 to 4 days so each fits one isolated worktree. A package is `verified` only when its acceptance tests pass on Windows (and on macOS where stated).

**User decision 2026-11-06 (ALL AT ONCE):** 1.2.0 ships only when the WHOLE app is Rust + Tauri v2 with full parity. There is no Node sidecar in the shipped app; Node is only a build tool (Vite for the React UI, vitest, scripts). The earlier staged plan (Node SEA sidecar in 1.2.0, ports in 1.3.0 to 1.6.0) is superseded; its sidecar-only packages (S2 SEA spike, A3 sidecar supervision, A4 Electron shim, A5 forked hosts, A7 sidecar WS server, P3b `--host=ssh`, N2 blob protocol for WS payloads, B2 state mirror/route flip, I10 sidecar removal, R1 to R4 intermediate release sweeps) are dropped and the 1.3.0 to 1.6.0 packages are folded into 1.2.0 below.

## Rules for every package

- Branch off `tauri-1.2.0` into its own worktree (`git worktree add ../unimux-wt-<id> -b tauri/<id>`); unlink node_modules junctions before removing the worktree.
- Stay inside the package's own files: `src-tauri/crates/unimux-<domain>/`, `src-tauri/crates/unimux-app/src/commands/<domain>.rs` (pre-created by F3), the domain's renderer files and `test/`. New workspace dependencies are one line in `[workspace.dependencies]`; on merge conflicts in Cargo.lock / package-lock.json take the target branch's file and rebuild.
- Port behaviour, not structure: the TS source in `src/main` stays in the tree as the reference until R1. Every ported vitest case gets a `#[test]` and a row in `test/PORTING.md`.
- Every new user-facing string goes through `tr()` with pl/en/de/es/fr/pt (Rust dialogs use `unimux_core::i18n::translate` over the generated `gen/messages.json`).
- Never touch the real `%APPDATA%\unimux`, `~/.claude`, `~/.codex`; real-app checks run the `check` flavour with `MC_DATA_DIR` and a scratch home (F13). Never kill electron.exe or unimux.exe processes the agent did not start. Docker: remove only your own containers by id, never prune.
- Acceptance has three kinds: **cargo** (unit/integration tests, goldens), **vitest** (TS adapter and renderer), **real-app** (the built `check` app driven over WebView2 CDP by a script in `scripts/`). A package is not verified while any of its listed checks is missing.
- "Not yet" contract: until a package implements a command, F3 answers it with the typed `McNotYetError` (`code: 'MC_NOT_YET'`). The contract counter (`npm run ipc:report`) must show every package's commands as implemented before it is marked done.
