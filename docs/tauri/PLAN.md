# unimux Tauri migration: work packages

See ARCHITECTURE.md for the design. Effort is in agent-days (one agent, one working day). Packages are sized 1 to 4 days so they fit one worktree each. A package is "verified" only when its acceptance tests pass on Windows (and on macOS where stated).

Totals:

| Release | Packages | Effort (agent-days) |
|---|---|---|
| 1.2.0 (Tauri shell + Rust pty + Node sidecar) | 34 | 98 |
| 1.3.0 (git, files, agents infra) | 16 | 50 |
| 1.4.0 (SSH, shell spawn, SFTP) | 13 | 42 |
| 1.5.0 (databases) | 13 | 46 |
| 1.6.0 (accounts, state, MCP, automation; sidecar removed) | 17 | 62 |
| **Total** | **93** | **298** |

Add 20 to 25 percent for integration and fix cycles. 1.2.0 with 5 to 6 parallel agents: critical path about 35 working days (S2 -> A1 -> B1 -> A2 -> A3 -> A4 -> A7 -> A10 -> A17 -> A18 -> A19 -> A20, with A14 -> A15 -> A16 finishing in parallel), so about 7 to 8 calendar weeks including the manual Windows VM and Mac checks. 1.2.0 cannot honestly ship "now".
